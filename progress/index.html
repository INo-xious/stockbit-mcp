Drawing

Partial

Levels, zones, trend lines and markers drawn on the rendered chart; the same levels written into generated Pine; and your OWN saved Stockbit drawings readable as context via chart_layout. Writing drawings INTO the account is not done — it needs POST /chartbit/{symbol}/layout, which mutates your account and supersedes ADR-0002.

price_chart chart_layout pine_script

Verified: Live: chart_layout reads GET /chartbit/{symbol}/layout (HTTP 200) plus chart metadata. The save format is now fully recovered from Stockbit's own bundle (docs/chartbit-layout-format.md) — Fj is a string substitution, not encryption, and the payload is plain TradingView chart state. The encoder, composer and round-trip are implemented and tested (layoutcodec).

Blocked: Needs your explicit yes: POST /chartbit/{symbol}/layout overwrites your saved chart. The payload is ready and tested; no write route exists until you say so. Separately, composing BRAND-NEW drawings needs the TradingView line-tool schema, which Stockbit serves only to an authenticated chart page — reading and round-tripping a layout does not need it.

Alerts

Done

Rule engine sharing one indicator registry with the Pine emitter, so an alert and its alertcondition agree — plus a standalone daemon (`stockbit-alerts watch`) that polls during IDX hours and delivers. Three channels: an append-only JSONL log (always, written first), a native desktop notification (default on, no setup), and an optional https webhook. Fires once per bar; reports warm-up separately from a false condition.

alert_create alert_list alert_delete alert_check stockbit-alerts (CLI)

Verified: Live: two rules fired on BBRI with correct values (close 3020 > 2000; RSI 56.18 < 70), Windows toasts delivered, log written; the next pass fired 0, confirming same-bar suppression.

Workflow automation

Done

Five saved recipes — deep_dive, morning_scan, bandar_watch, alert_sweep, pine_handoff — each running several tools in one call, the same way every time. Declarative steps only: no eval, a closed template vocabulary, capped fan-out that reports what it skipped, and a failing step that aborts and names itself unless marked optional.

workflow_list workflow_run

Verified: Live: deep_dive on BBRI ran all four steps green in 3.7s (quote, technicals, chart, broker distribution).

UI automation on graphics

Declined

Deliberately not built. Stockbit Desktop is Tauri/WKWebView with no CDP, and Stockbit exposes a clean JSON API this server already reads — so driving a GUI would solve a problem that does not exist. The practical substitute is opening the real Stockbit chart in your own browser beside what was drawn.

Backtesting

Done

Nine preset strategies plus custom conditions in the same grammar the alerts and the Pine emitter share. Next-bar fills, stops win ties, gaps fill at the open, ARA/ARB-locked sessions are unfillable, buy-and-hold benchmarked over the same window. Walk-forward with a verdict that reaches 'inconclusive' before it reaches 'robust'.

Verified: Absence of lookahead proved structurally: a backtest over the first N bars is a prefix of the backtest over all bars, asserted across nine presets, three cut points and 100+ trades.

Blocked on a decision

  • Chartbit writes are ENABLED under ADR-0003 with their full apparatus (snapshot, verify, rollback, mutation log) — and Stockbit's end discards them. Both POST routes answer 200 and store nothing; eliminated across nine variables, and their own web bundle has no save wiring either. Not a blocker this project can clear.
  • Composing brand-new drawings needs the TradingView line-tool schema (what `state` a LineToolHorzLine expects). Stockbit serves the charting library only to an authenticated chart page, so it could not be read the way the rest of the format was. Reading, round-tripping and modifying an existing layout does not need it.

Worth knowing
